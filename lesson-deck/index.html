Presentations as Code

Using Claude Code + Reveal.js to build adaptive product walkthroughs.

A two-deck session: this lesson, plus a generated Pet Coach product journey.

Welcome the audience. Explain that this session is about using AI coding agents to create presentation artifacts that go beyond linear slides. Frame the structure: this lesson deck, then we switch to a generated Pet Coach product journey deck and treat it like an app demo. Tell the audience the second deck is the artifact — the thing we built using Claude Code.
The Problem

Linear decks are useful, but they force one path.

  • Great when there is a single planned story.
  • Awkward when the audience wants selective depth.
  • Complex topics often become either too shallow or too long.
  • Backup detail gets buried in appendices, or skipped entirely.
Set up the problem: many product and technical conversations need both a simple main path and optional detail. We can usually do one well, but not both. Ask the audience: when did you last present a topic where half the room wanted the executive summary and the other half wanted the data model?
Why Now

AI coding agents lower the barrier to technical frameworks.

  • Reveal.js has existed for over a decade.
  • Many people avoided it because it required web-development comfort.
  • Claude Code can scaffold, revise, refactor, and maintain the deck.
  • Non-specialists can now reach for more powerful tools by describing the artifact they need.
Coding agents expand the scope of tools people can use in their everyday work.
Make clear that the value is not "non-technical users become developers overnight." The value is that software-shaped tools become more approachable. The audience should leave understanding that the bottleneck has shifted from implementation skill to clarity of intent.

Tool Fit

Not better than PowerPoint — different.

Best for

PowerPoint · Claude Cowork · Claude Design

  • Polished linear decks.
  • Executive-ready visuals.
  • Familiar editing and review.
  • Business handoff and reuse.
  • Fast first draft.
Best for

Reveal.js + Claude Code

  • Adaptive talks.
  • Product journey walkthroughs.
  • Optional deep dives.
  • Embedded prototypes.
  • Architecture and data diagrams.
  • Source control and web publishing.
Keep this objective. Reveal.js is not a universal replacement. If you'd ship the deck as a PDF for an exec review, PowerPoint is probably right. If the deck is the product walkthrough that lives in a repo and gets re-presented, Reveal.js earns its place.

Demo Scenario

Pet Coach — an AI-assisted veterinary triage app.

Pet Coach helps pet owners:

  • Triage symptoms before deciding on a clinic visit.
  • Determine whether a clinic visit is recommended, and how soon.
  • Schedule the visit and save pre-visit context for clinic staff.
  • Ask follow-up questions about diagnostics, prescriptions, and care.

Pet Coach is a fictional product, framed as a support tool — not a substitute for veterinary care.

Set up the demo deck. The Pet Coach scenario was chosen because it has natural decision points and natural depth: clinical safety, data handoff, architecture, and follow-up education. Audience should feel "this is a real product I could imagine reviewing."
The Artifact

The demo deck is the artifact.

  • Horizontal slides show the quick user journey.
  • Vertical slides show optional depth where it matters.
  • Selected verticals include lightweight UI mockups.
  • Technical deep dives cover data, architecture, and safety boundaries.
  • The same artifact supports product, UX, architecture, and leadership conversations.
Emphasize that the Pet Coach deck is not just a presentation — it is a navigable product model. The same file serves the PM, the architect, and the exec because each path is genuinely available.

  • The deck became navigable, not just linear.

Prompting Lessons

What to tell the coding agent.

  • Define the audience and purpose.
  • Specify horizontal vs vertical structure explicitly.
  • Provide the journey outline up front.
  • Identify which steps need deep dives.
  • Ask for speaker notes.
  • Ask for reusable styling (cards, badges, panels).
  • Add UI prototype and architecture requirements in stages.
Point out that the quality of the generated artifact depends heavily on structural prompting. Good prompts don't just describe content — they describe shape. The next slide shows the actual prompt snippet that made this whole artifact possible.
Prompting Lessons · Live Example

Specify the structure in one line.

Excerpt from the actual prompt that produced the Pet Coach demo deck: 


## Core concept to demonstrate

The class should be able to see this pattern clearly:

```
Horizontal navigation = main product journey
Vertical navigation = optional detail under a journey step
```

The presenter should be able to move left-to-right through the
quick path, or move downward from selected parent slides to
explore details.

Press → to step the highlighted line through the snippet. Two lines of structural intent did most of the work.

This is the "prompt → artifact" payoff. Walk through the highlighted lines: first the section header, then the two-line declaration of shape, then the navigation expectation. Mention that everything else in the prompt was content — but those two lines defined the artifact.
Risks & Limits

Where this can go wrong.

  • Too much hierarchy can become a maze.
  • Generated UI may look plausible but isn't validated.
  • Technical setup may still need a knowledgeable reviewer.
  • Brand and accessibility need deliberate review.
  • PowerPoint may still be better for formal executive decks.
Keep this balanced and credible. The goal is not to convince the room that Reveal.js is the answer — it's to give them a clear sense of when to reach for it. Honest limits build trust.
Takeaways

What to carry out of this room.

  • AI coding agents make technical frameworks accessible to more people.
  • Reveal.js is useful when a deck needs optional depth.
  • Product journeys are a natural fit for two-dimensional presentation structure.
  • One artifact can connect story, UI, data, and architecture.
  • The pattern applies far beyond Reveal.js — anywhere a tool was "out of reach."
End with the broader pattern: AI lets people create structured artifacts that previously required specialized implementation skills. The deck is one example. Spreadsheets, infrastructure-as-code, dashboards, prototypes — same pattern.
